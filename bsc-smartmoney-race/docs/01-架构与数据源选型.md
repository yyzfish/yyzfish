# 01 · 架构与数据源选型

> 调研截止 2026-08-15。标 ⚠️ 的是第三方转述或需自行复核，标 ❌ 的是**没搜到确切数字，不要当事实用**。

---

## 0. 三条会改变架构的前置事实

**① BSC 出块已经是 0.45 秒，不是 0.75s。**
Fermi 硬分叉 2026-01-14 主网生效（BEP-619 第三阶段）。约 **192,000 区块/天**。
任何按区块轮询的追踪器，轮询间隔必须 < 450ms 才不丢块 —— 结论是实时链路**一律用 WSS / gRPC 推送，不要轮询**。
另注意：Fermi 引入了新的日志索引机制（从区块 59,484,738 起），节点启动时会吃大量 CPU，可用 `--history.logs 600000` 限制范围。

**② BSC 上不存在可用的现成钱包 PnL API。**
Moralis 的 profitability 端点当前只覆盖 Ethereum / Polygon / Base，**不含 BSC**。
即便将来支持，其口径也有硬伤：只算已实现、**不含 gas**、**只识别 Uniswap V2/V3 事件**（意味着 Pancake V3 的自定义 Swap 和 Infinity 的 singleton 事件极可能解析不到）。
⇒ **PnL 引擎必须自建**。数据源的选择标准因此变成「谁能最便宜地喂给我完整的 swap 明细」，而不是「谁的 PnL 算得准」。

**③ Pancake V3 ≠ Uniswap V3，Infinity 更是另一套架构。**
V3 的 Swap 事件多了 `protocolFeesToken0/1` 两个字段，topic0 完全不同；费率档也不同（0.25% / tickSpacing 50）。
Infinity 是 **singleton**：Swap 从 `CLPoolManager` / `BinPoolManager` 单一合约发出，用 `PoolId(bytes32)` 区分池子 —— V2/V3 那套「按 pair 地址订阅」的逻辑完全失效，必须先用 `Initialize` 事件建立 `PoolId → (currency0, currency1, fee, hooks)` 映射表。
直接抄 Uniswap 的解析器会**漏掉全部 V3 和 Infinity 交易**。

## 2. 推荐分层架构

```
                    ┌──────────────────────────────────────────────┐
   L1 实时层  ─────▶│ Bitquery CoreCast gRPC (~300ms)              │
   （秒级跟人）      │ Pancake V2/V3/Infinity swap + Four.meme 事件  │
                    │ + mempool（Scale 档）                         │
                    └──────────────────┬───────────────────────────┘
                                       │
   L2 回填层  ─────▶ Envio HyperSync (bsc.hypersync.xyz)
   （历史全量）       eth_getLogs 级原始事件 → 喂自建 PnL 引擎
                                       │
   L3 校验层  ─────▶ Dune SQL (dex.trades on bnb)
   （交叉验证）       离线批量算分、与自建结果对账
                                       │
   L4 兜底层  ─────▶ NodeReal / Ankr RPC + 自建 archive 节点
   （trace/补数）     余额快照、trace、L1 断流时补数
```

**成本区间**

| 项 | 低配（PoC） | 中配（生产） |
|---|---|---|
| Bitquery | $79（Pro，无 mempool） | **$239（Scale）** |
| Bitquery 历史包 | $0（30 天内够用） | +$70–150 ⚠️ |
| Dune | $0（Free） | 需自行核价 ⚠️ |
| RPC | $31（NodeReal Growth） | $159（Team） |
| Envio | $0（开发档） | ❌ 未知 |
| 自建 archive | $0 | ~$300–600 ⚠️ **估算，未询价** |
| **合计** | **约 $110/mo** | **约 $1,200–1,500/mo** |

## 3. 标的范围：Meme / 新币

**Four.meme 主合约**：`0x5c952063c7fc8610ffdb798152d69f0b9550762b`
**核心事件**：`TokenCreate` / `TokenPurchase` / `TokenSale` / `LiquidityAdded` / `PairCreated` / `PoolCreated`

**Bonding curve**
```
总供应量   1,000,000,000
曲线可售     800,000,000   (initialRealTokenReserves)
毕业预留     200,000,000   (毕业时注入 PancakeSwap V3 做初始流动性)

BondingCurveProgress = 100 − (leftTokens × 100 / initialRealTokenReserves)
```

**三个必须处理的坑**

1. **曲线阶段的交易不在任何标准 DEX 索引里。** Four.meme 用自定义 exchange 合约，`dex.trades` 看不到。想覆盖「从发射到毕业」的完整生命周期，必须单独解析 Four.meme 事件 —— 这是聪明钱系统最容易漏的一段，而恰恰是 **alpha 最集中的一段**。
2. **毕业事件从 Four.meme 合约发出，不是从 Pancake Factory 发出。** 监听 Factory 的 `PoolCreated` 能拿到，但归因会错（`msg.sender` 是迁移合约）。
3. **TokenManager 有 V1 / V2 两代合约**，只索引 V2 会丢失早期代币的完整历史。

**Binance Meme Rush** 不是独立平台，是 Binance Wallet 内的发现入口、底层由 Four.meme 提供。通过它发的代币**合约地址以 `0x4444` 开头** —— 一个极便宜的高价值过滤特征。

其他平台（⚠️ 市占率数据来自 DWF Labs 研报，明显偏旧，需自行用链上数据重算）：GraFun（毕业阈值 38.75 BNB）、Flap（16 BNB）。三家**全部毕业到 PancakeSwap V3**。

```
# PancakeSwap V2

# PancakeSwap V3
Factory   0x0BFbCF9fa4f9C56B0F40a671Ad40E0805A091865
Router    0x1b81D678ffb9C0263b24A97847620C99d213eB14

# PancakeSwap Infinity（singleton）
CLPoolManager     0xa0FfB9c1CE1Fe56963B0321B32E7A0302114058b
BinPoolManager    0xC697d2898e0D09264376196696c51D7aBbbAA4a9
UniversalRouter   0xd9C500DfF816a1Da21A48A732d3498Bf09dc9AEB
```

| 协议 | topic0 |
|---|---|
| Pancake V2 Swap | `0xd78ad95fa46c994b6551d0da85fc275fe613ce37657fb8d5e3d130840159d822` |
| Pancake V3 Swap | `0x19b47279256b2a23a1665c810c8d55a1758940ee09377d4f8d26497a3577dc83` |
| Infinity CL Swap | `0x04206ad2b7c0f463bff3dd4f33c5735b0f2957a351e4f79763a4fa9e775dd237` |

> ⚠️ ABI 来自 PancakeSwap 官方仓库确证，但 **V3 / Infinity 的 topic0 是本地 keccak 计算的，未找到第三方文档直接印证**。上线前务必用一笔真实 BSC 交易的 log 核对。
> ❌ Infinity **Bin 池**的 Swap 事件 ABI 未取到，需自行从 `IBinPoolManager` 确认。

**归因**：V3 的 `recipient`、Infinity 的 `sender` 几乎总是 Router。必须回退到 `tx.from` 或解析 UniversalRouter 的 calldata —— 搞错了会把成千上万个用户全归成一个「Router 地址」。

## 5. 落地顺序建议

| 阶段 | 目标 | 数据源 | 产出 |
|---|---|---|---|
| **W1–2** | 打通离线赛马 | Dune Free + Envio 免费档 | 90 天历史的选手榜单，跑通闸门 |
| **W3–4** | 校准与反作弊 | + Bitquery Pro | 净化规则调参、可跟单性回测 |
| **W5–6** | 上实时层 | + Bitquery Scale（mempool） | 头部选手秒级告警 |
| **W7+** | 降本 / 自主 | + NodeReal + 自建 archive | 摆脱单一供应商，历史可无限回溯 |

**上线前必须自行验证的清单**

- [ ] `SELECT DISTINCT project, version FROM dex.trades WHERE blockchain='bnb'` —— Infinity 是否已收录
- [ ] Bitquery archive 数据集是否额外计费、历史深度上限（问销售）
- [ ] NodeReal 的 BSC 是否含 archive / trace / WebSocket
- [ ] 用一笔真实交易 receipt 核对 V3 / Infinity 的 topic0
- [ ] Dune / Envio 各档的确切月费与赠送额度（官网直核，勿信第三方转述）
- [ ] Four.meme TokenManager V1 / V2 的完整地址与 ABI（从 BscScan 已验证合约提取）
