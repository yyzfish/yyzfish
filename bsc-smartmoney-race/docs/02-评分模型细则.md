# 02 · 评分模型细则

> 本文是框架的核心。所有阈值都在 `smrace/config.py`，所有公式都在对应模块里有实现。
> 标注约定：**[有出处]** 有公开文档/论文支撑；**[行业做法]** 广泛使用但无权威出处；**[工程判断]** 本框架的设计决策。

---

## 0. 一句话总纲

**先净化，再赛马，最后过统计闸门；序数定「强不强」，基数定「能不能换成钱」，可跟单性回测定「你能拿到多少」。**

```
ingest → ① 实体聚类 → ② PnL 结算 → ③ 净化 → ④ 基数指标
       → ⑤ 赛马 Elo-MMR → ⑥ 统计闸门 → ⑦ 可跟单性回测 → ⑧ 选手池 → ⑨ 实时告警
```

顺序不可颠倒。两条最容易被跳过、跳过就全盘皆输的：

- **① 必须在 ② 之前**：不合并 sybil，一个操盘手 20 个分身里运气最好的那个就会以「高手」身份进入评分，它 19 个亏损兄弟被榜单忽略 —— 幸存者偏差 + 选择偏差的组合。
- **③ 必须在 ⑤ 之前**：不剔除 MEV / bundler，任何按胜率排序的榜单榜首**必然**是它们（狙击机器人 87% 胜率有实证支撑）。

## 1. PnL 口径

实现：`smrace/pnl/engine.py`

### 1.1 成本法 —— 移动加权平均

行业已收敛到加权平均（Nansen、Dune 官方教程口径一致）**[有出处]**。

设持仓量 $q$、成本池 $C$（USD）：

$$
\text{买入 }\Delta q\text{ 花费 }c:\quad q \mathrel{+}= \Delta q,\quad C \mathrel{+}= c
$$
$$
\text{卖出 }\Delta q\text{ 收到 }p:\quad \text{avg}=\frac{C}{q},\quad \text{Realized} \mathrel{+}= p - \text{avg}\cdot\Delta q,\quad C \mathrel{-}= \text{avg}\cdot\Delta q,\quad q \mathrel{-}= \Delta q
$$
$$
\text{Unrealized} = q\cdot P_{\text{mark}} - C
$$

**为什么不用 FIFO**：memecoin 上同一地址对同一代币常有几十次分批买卖，FIFO 要维护 lot 队列且对「先卖哪一批」的假设敏感；加权平均路径无关、$O(1)$ 状态，且与 Nansen/Dune 口径一致便于对标。
**代价**：抹平「早期低价筹码 vs 后期追高筹码」的区别，无法度量分批建仓能力。
**建议**：主口径用加权平均，**并行**维护 FIFO 用于「持仓时长分布」「首笔进场价相对代币 ATH 的分位」这类需要 lot 级信息的指标 **[工程判断]**。

### 1.2 定价 —— 用实际执行价，不要用外部 K 线

$$P_{\text{exec}} = \frac{\text{quote\_amount}\times P_{\text{quote}}}{\text{base\_amount}}$$

Nansen 的主口径同样是 "Counterparty Token Price"（该笔 swap 的实际执行价），仅纯转账才退回市价 **[有出处]**。

**这条必须照抄**。用预言机/K 线价格给 swap 定价会系统性低估滑点，在低流动性 memecoin 上误差可达数十个百分点。
**推论**：滑点已被执行价吸收，**不要再单独扣一次滑点**。

quote 侧需要喂 USD 价的资产：`WBNB / USDT / USDC / BUSD / USD1 / CAKE`。

### 1.3 转入转出 —— 最大的坑

**转入不按零成本，按转入时市价记成本**（Nansen 同口径）**[有出处]**。含义是：转账被视为「视同卖出 / 视同买入」，PnL 归属转出方。

| 场景 | 错误做法 | 本框架规则 |
|---|---|---|
| 空投 / 免费领取 | 成本 0 → **虚增无穷大 ROI** | 成本 = 领取时市价；打 `airdrop` 标记，**从「交易能力」评分中剔除** |
| 跨链桥转入 | 记为买入 → 虚增买入量 | 桥合约白名单 → `bridge_in`，成本 = 转入时市价 |
| 同实体内部转账 | 双方各算一次 → **同笔盈利重复计 2 次** | 先做实体聚类，簇内转账**净额抵消**，不产生 PnL 事件 |
| CEX 提币转入 | 无法知道 CEX 内成本 | 成本 = 转入时市价，并置 `has_offchain_leg = true`，该实体 PnL 置信度降级 |
| LP / 质押 | `addLiquidity` 被误读成「卖 A+B、买 LP token」→ **巨额虚假 realized PnL** | `add/removeLiquidity`、`stake/unstake` 标记为 **PnL 中性**；`harvest` 记零成本收入并单独标记 |

**硬性一致性检查（必须实现）**

```
对每个 (entity, token):
    coverage = Σ(有明确链上买入对价的流入 USD) / Σ(所有流入 USD)
    coverage < 0.80              → 该仓位标 low_confidence
对每个 entity:
    transfer_in 占流入 USD > 30% → 整个实体不进入排行榜
```

不做这一步，一个「收币 → 卖出」的老鼠仓地址会显示为零成本、无限 ROI —— 各类榜单最常见的污染源。

### 1.4 净 PnL —— 排行榜只能用这个

$$\text{NetPnL} = \text{Realized} + \text{Unrealized} - \sum \text{gas}_{\text{usd}} - \sum \text{tax}_{\text{token}}$$

四项必须计入的 BSC 特有成本 **[工程判断]**：

1. **Gas**：`gasUsed × effectiveGasPrice × P_BNB(t)`。**失败交易的 gas 也要算** —— 狙击机器人失败率极高，只算成功交易会严重高估其净收益。
2. **代币转账税（fee-on-transfer）**：BSC 上大量 memecoin 有 3–10% buy/sell tax。实际到账 ≠ Swap 事件的 amountOut，**必须用 ERC20 `Transfer` 事件的实际到账量**。
3. **MEV 保护 / priority fee**：通过 48Club Puissant、bloXroute 等私有通道发送的交易有额外 bribe，体现为对 validator 的直接转账，需从 trace 提取。
4. **滑点**：已由 1.2 的执行价口径吸收，**不要重复扣**。

> Gross PnL 榜单会把高频机器人排到最前面。这不是风格问题，是对错问题。

## 2. 实体聚类（反 Sybil）

实现：`smrace/normalize/entity.py`

规则借鉴 Wormhole 空投反女巫实践（ownership clustering / source-of-funds / behavioral clustering / tx spam）**[有出处]**。

| 规则 | 判据 | 强度 |
|---|---|---|
| **A 共同资金源** | 同一地址在 ±1h 内向 ≥5 个地址转出**数额相对差 ≤5%** 的原生币（diffusion funding） | 强 |
| **B gas 加注方** | 某地址首笔 BNB 流入全部来自同一 EOA（非 CEX 白名单） | 强（被 A 覆盖） |
| **C 同区块共现** | `Jaccard(建仓区块集合) > 0.6` 且共现次数 ≥ 5 | **弱，必须与 D 联合** |
| **D 代币重合度** | `Jaccard(交易过的代币集合) > 0.7` 且首买区块差中位数 ≤ 3 | 中 |
| **E 利润归集** | 多个地址的资金最终汇入同一地址 | **最强** |

**⚠️ C 不能单用。** 热门时段本来就有大量无关地址同块建仓。本框架要求 C 与 D 同时成立才合并 —— **过度合并会把两个互不相干的操盘手判成同一人，比漏合并更难排查**。

工程细节：用「至少共享一个代币」的倒排索引把候选对压到可控范围，避免 $O(N^2)$；参与者 > 400 的热门币跳过共现判定（无信息量）。

外部先验：Arkham 的 Entities（地址簇）是现成的高质量输入，Arkham 没有 smart money 概念但**实体聚类正是它的强项**；其 `FOMO User` 标签可作为负向特征 **[有出处]**。

## 3. 净化：污染模式与剔除顺序

实现：`smrace/purify/filters.py`

### 3.1 污染模式速查

| 模式 | 榜单表现 | 判据 | 跟单可复制性 |
|---|---|---|---|
| **Bundler** | 极高胜率 | `block_delta == 0`（与建池同块） | **绝对不可能** |
| **Sniper** | 高胜率、极短持仓 | `block_delta ∈ [1,3]`；实证 55% 在 1 分钟内退出、约 85% 在 5 分钟内 **[有出处]** | 极低 |
| **三明治 MEV** | 高频微利、胜率 >95% | 同块反向 swap 且 $T_{A2}$ 输入量 == $T_{A1}$ 输出量；中位持仓 < 1 块 **[有出处]** | 无 |
| **Bump bot（刷量）** | 交易量巨大、PnL≈0 | `flip_ratio = #flips / |Δnet position| > 50` **[有出处]** | 无 |
| **Wash trading** | 笔数极多、净头寸≈0 | SCC 循环出现 ≥100 次 **+** 镜像成交确认 **[有出处]** | 无 |
| **老鼠仓 / 内部** | 零成本或无限 ROI | 发币者 → 该地址的 pre-launch 转账；transfer_in 占比高 **[有出处]** | 无 |
| **Sybil 分仓** | 若干「完美」小地址 | 见第 2 节 | 无（是幸存者偏差） |
| **空投卖出** | 无限 ROI | transfer_in 无对价 | 无 |

### 3.2 Wash trading 的两级判定

单靠 SCC 误报很高 —— **正常交易者反复买卖同一批热门币也会成环**。本框架用两级 **[工程判断]**：

1. **候选生成**：按代币构建「卖方 → 买方」有向图，Tarjan 求 SCC，出现次数 ≥ 100（Victor & Weintraud 阈值）**[有出处]**。
2. **成交量匹配确认**：同块或相邻块出现**金额相对差 ≤ 1%** 的反向成交（= 净头寸变化≈0，即 CFTC 定义的「未承担市场风险、未改变持仓」）；同一对地址镜像成交 ≥10 次且跨 ≥3 个代币才判定。

时间窗从原文的 1 小时 / 1 天 / 1 周收紧到 **1 分钟 / 1 小时 / 1 天** —— memecoin 生命周期远短于 2021 年的 ERC20。

### 3.3 剔除顺序（8 步）

```
1. 实体聚类合并（sybil）
2. 剔除  block_delta == 0                  → bundler
3. 剔除  中位持仓 < 1 块                    → 三明治 MEV
4. 剔除  flip_ratio > 50                    → bump bot
5. 剔除  SCC + 镜像成交确认                 → wash trader
6. 剔除  transfer_in 占流入 USD > 30%        → 成本基准不可信
7. 分流  block_delta ∈ [1,3]                → sniper 赛道（不删！）
8. 剔除  交易笔数 < 20                       → 样本不足
```

**第 7 步是关键设计取舍。** Sniper 是真实的赚钱者，其 alpha 来自发射前信息优势 + 同块执行特权，跟单者 100% 无法复制。所以：
**不删除，单独分赛道 —— 作为「信号源」（它们买了什么）而非「跟单对象」。**

一个佐证：已有研究指出 bundler / sniper **不改变代币的总收益池，只是把利润从跟单者转移到自己** —— 跟单者是这个零和再分配的付款方 **[有出处]**。

## 4. 赛马机制

实现：`smrace/race/engine.py` + `smrace/scoring/elo_mmr.py`

### 4.1 比赛的定义 —— 整个框架的核心

```
一场比赛 = 一个代币 × 一个时间窗（默认 24h，每个代币取前 3 个窗口）
参赛选手 = 窗口内对该代币建立过仓位、且投入 ≥ $50 的所有实体
名次     = 窗口内净收益率降序
```

**为什么这样映射**：名次是**同一代币内的横截面比较**，因此自动剔除了代币本身的 beta。memecoin 牛市里所有人都赚、熊市里所有人都亏 —— 横截面排名天然中性化了这个周期因子。这是「赛马」相对「绝对 PnL 榜单」的本质优势。

### 4.2 平局判定 —— 一个会毁掉整个评分的坑

收益率差 < `draw_margin_ret`（默认 5%）视为平局。**但必须与所在并列组的组首比较，不能与前一名比较。**

> 如果用相邻间距判并列：memecoin 一场比赛里收益率往往是连续分布的（大家都亏 55%~65%），相邻间距永远小于阈值 ⇒ **全场并列第一**，名次信息完全丢失，Elo 退化成噪音。
> 本框架的实测中这个 bug 曾让所有选手的名次分位统计量整体上偏（赌徒中位 z 从 −0.19 被抬到 +4.27），完全掩盖真实信号。`tests/test_core.py::test_rank_entries_does_not_collapse_everyone_into_first` 锁住这个行为。

### 4.3 为什么是 Elo-MMR(ρ)，不是 Elo / Glicko-2 / TrueSkill

| 系统 | 问题 |
|---|---|
| **Elo** | 两两对战模型，本场景是「N 人对同一批标的下注」的 free-for-all |
| **Glicko-2** | 存在 **volatility farming** 漏洞：故意打出差表现抬高 $\sigma$，随后一次好表现获超额加分。**在有金钱激励的加密场景中这必然被利用** **[有出处：Elo-MMR 论文 Thm 5.5 明确指出]** |
| **TrueSkill** | FFA 支持好，$\mu-3\sigma$ 的保守展示值非常有用 —— **本框架采用这一条做展示值** |
| **Elo-MMR(ρ)** ✅ | 专为大规模多人竞赛设计；log-cosh 损失在原点像 L2、尾部像 L1 ⇒ **鲁棒平均，自动降权极端表现**；论文 Thm 5.5 证明**激励相容**（追求评分最大化者永远不想故意表现更差） |

**这一点对 memecoin 极其关键**：一次 1000× 的运气爆发不会让评分冲到榜首，而按 PnL 求和的榜单会。

### 4.4 公式

**Stage 1 · 表现估计** —— 解 $Q_i(p)=0$，即「期望名次 == 实际名次」的表现水平（不做两两比较，用相邻比较约束）：

$$
Q_i(p) = \sum_j w_j\Big[-\tanh\big((p-\mu_j)a_j\big) + c_{ij}\Big],\qquad
w_j=\frac{\pi}{\sqrt3\,\sigma_j},\quad a_j=\frac{w_j}{2}
$$

$$
c_{ij} = \begin{cases}-w_j & j\text{ 名次优于 }i\\ 0 & \text{平局}\\ +w_j & j\text{ 名次劣于 }i\end{cases}
$$

其中 $\sigma_j=\sqrt{\sigma_j^2+\beta^2}$。用带自动扩张括号的二分法求根。

**Stage 2 · 评分更新** —— 解 $L'(s)=0$：

$$
L(s)=L_2\!\left(\frac{s-p_0}{\beta_0}\right)+\sum_k L_R\!\left(\frac{s-p_k}{\beta_k}\right),
\qquad L_R(x)=2\ln\cosh\!\left(\frac{\pi x}{\sqrt{12}}\right)
$$

$$
L'(s)=\frac{2(s-p_0)}{\beta_0^2}+\sum_k \frac{2\pi}{\sqrt{12}\,\beta_k}\tanh\!\left(\frac{\pi(s-p_k)}{\sqrt{12}\,\beta_k}\right)
$$

**扩散（不确定性增长）**：

$$
\sigma_d=\sqrt{\sigma^2+\gamma^2},\qquad \kappa=\frac{\sigma^2}{\sigma_d^2},\qquad \beta_k \leftarrow \frac{\beta_k}{\sqrt\kappa},\qquad
\frac{1}{\sigma'^2}=\frac{1}{\sigma_d^2}+\frac{1}{\beta^2}
$$

$\gamma$ 就是系统对抗 **alpha 衰减**的机制：长期不参赛的选手不确定性自动上升，展示分自动下滑。

**ρ**：只保留最近 $\rho$ 项历史 logistic 项（默认 30），更早的丢给正态锚点。

**展示值**：

$$\boxed{\text{display} = \mu - 3\sigma}$$

TrueSkill 式保守分位。样本少 ⇒ $\sigma$ 大 ⇒ 展示值低。**这一条直接解决「4 笔交易 100% 胜率」的问题。**

> 已知简化（相对论文）：$\sigma$ 更新用高斯近似 $1/\sigma'^2=1/\sigma_d^2+1/\beta^2$。

**默认参数**：$\mu_0=1500$，$\sigma_0=350$，$\beta=200$，$\gamma=40$，$\rho=30$，$\sigma_{\min}=40$。
评分周期长度建议取「让中位活跃实体每期参与 10–15 场」，Glicko-2 官方规范给的经验值 **[有出处]**；BSC memecoin 场景大致对应 **1 周**。

## 5. 统计闸门 —— 最容易被跳过、也最致命的一层

实现：`smrace/scoring/gates.py`

### 5.1 问题陈述

从 10,000 个地址里按 PnL 挑前 100 名，**即使所有地址都是零 alpha 的赌徒，你也一定能挑出「看起来很神」的一批。**

**先验参照**：Barras-Scaillet-Wermers 对 2,076 只共同基金（1975–2006）的分解结论 —— 零 alpha 75.4%、负 alpha 24.0%、**费后真有技能仅 0.6%**（费前 9.6%）**[有出处]**。
在受监管、有披露、有专业团队的行业里尚且如此；匿名、高摩擦、充斥机器人的 BSC memecoin，先验上应预期真聪明钱占比是**个位数千分比甚至更低**。

> 顺带一提：有 memecoin copy-trading 研究把 smart money 定义为「平均收益 > 0 且收益 t 统计量 > 1.645」**[有出处]**。在 6,000 个项目、数万地址的选择空间下，**t > 1.645 几乎排除不了任何运气**。不要照抄这个门槛。

### 5.2 闸门 A · 序数（主闸门）

统计量：**名次分位均值**。

$$
H_0:\ \text{无技能}\ \Rightarrow\ \text{分位}\sim U(0,1),\quad \mathbb E=0.5,\ \operatorname{Var}=\tfrac1{12}
$$
$$
z=\frac{\bar p-0.5}{\sqrt{\dfrac{1/12}{n}}}
$$

**为什么它是主闸门**：**零假设方差是解析已知的（1/12），与收益分布形状完全无关。** 这正是「赛马」在统计上相对「PnL 榜单」的根本优势。

对比之下，Bailey & López de Prado 的 $E[\max SR]$ 公式

$$
E[\max\{\widehat{SR}\}]\approx\sqrt{V[\{\widehat{SR}\}]}\left[(1-\gamma)\Phi^{-1}\!\left(1-\tfrac1N\right)+\gamma\Phi^{-1}\!\left(1-\tfrac1{Ne}\right)\right],\ \gamma\approx0.5772
$$

要求 $V[\widehat{SR}]$ 是**零假设下**的方差。但 memecoin 人群的横截面 Sharpe 均值可以低到 $-0.63$ —— 横截面方差反映的是「真实技能离散度 + 系统性亏损」，**不是**零假设噪音幅度。直接代入会得到荒谬的高基准线（本框架实测 1.557），把所有人包括真高手一刀切掉。

**噪音基准线用置换检验标定** **[工程判断]**：

```
for b in 1..B:
    for each entity with n_i races:
        z_i^(b) = (mean(U(0,1)^{n_i}) − 0.5) / sqrt((1/12)/n_i)
    max_b = max_i z_i^(b)
floor = quantile(max_b, 0.95)
```

它直接回答：**「我榜首那个 z=8.5 的人，在纯运气世界里有多常见。」** 比解析公式更贴合真实相关结构，是整个闸门里最值得投入算力的一步。

**多重检验校正用 BHY（控制 FDR，允许任意相关结构）** **[有出处]**：

$$
p^{\text{BHY}}_{(i)}=\min\left[p^{\text{BHY}}_{(i+1)},\ \frac{M\,c(M)}{i}p_{(i)}\right],\qquad c(M)=\sum_{j=1}^{M}\frac1j
$$

**必须用 BHY 而不是 BH** —— 地址收益高度相关（大家买的是同一批代币）。
量级参照：$M=10{,}000$ 时 $c(M)\approx 9.79$，FDR=10% 下最小 p 值需 $\le 1.0\times10^{-6}$（约 $t\approx4.9$）。

### 5.3 闸门 B · 基数（经济显著性）

- 平均收益 > 0
- **Profit Factor** $=\dfrac{\sum_{r_i>0}r_i}{\left|\sum_{r_i<0}r_i\right|} \ge 1.2$
- **cluster bootstrap 置信下界 > 0**

Bootstrap **按代币分块**，不是按时间分块 **[工程判断]**：本场景最大的相关性来源是「同一代币上的所有交易」，对代币重采样才能正确暴露「这个地址的全部利润其实只来自 1 个代币」。
（时间序列 studentized block bootstrap + HAC 是 Sharpe 推断的标准做法 **[有出处：Ledoit & Wolf 2008]**，但在这里 cluster 维度更对症。）

### 5.4 ⚠️ 为什么 DSR 默认**不**作为硬闸门

Deflated Sharpe Ratio：

$$
\widehat{DSR}=\Phi\!\left[\frac{(\widehat{SR}-SR_0)\sqrt{T-1}}{\sqrt{1-\hat\gamma_3\widehat{SR}+\frac{\hat\gamma_4-1}{4}\widehat{SR}^2}}\right]
$$

它的推断假设收益近似 iid、偏度峰度温和。**memecoin 的单笔收益分布是「八成 −100%、少数 +10000%」，偏度可以到 5 以上，分母会塌陷，所有人的 DSR 都趋近 0 —— 包括真有技能的人。**

本框架的合成数据实测：开启 DSR 硬闸门时，**8/8 真高手被全部误杀**（843/843 全灭）。改为诊断字段后，同一份数据 main 赛道精确率 100%、召回率 75%。

⇒ `dsr_as_gate = False` 是默认。DSR 仍然计算并展示。若标的池换成流动性更好、分布更温和的资产，可以打开。

同理，**Sharpe 在 memecoin 上几乎没有意义**（$\sigma$ 被右尾支配）；Sortino 稍好但 $-100\%$ 是硬下界，下行方差同样失真。优先看 Profit Factor 与序数统计量。

### 5.5 报告 FDR 分解，而不是拍脑袋取 Top 50

$$
\hat\pi_0(\lambda)=\frac{W(\lambda)}{M}\cdot\frac{1}{1-\lambda}\ (\lambda=0.5),\qquad
\hat T^+_\gamma=\hat S^+_\gamma-\hat\pi_0\frac\gamma2,\qquad
\widehat{FDR}^+_\gamma=\frac{\hat\pi_0\gamma/2}{\hat S^+_\gamma}
$$

产出一句可以直接汇报的话：**「本期 843 个候选中，估计真有技能者约 18 个；按 FDR ≤ 10% 构造的跟单组合含 7 人。」**

### 5.6 MinTRL —— 榜单上最有用的一个字段

$$
\text{MinTRL}=1+\left[1-\hat\gamma_3\widehat{SR}+\frac{\hat\gamma_4-1}{4}\widehat{SR}^2\right]\left(\frac{Z_\alpha}{\widehat{SR}-SR^*}\right)^2
$$

直接告诉你「这个地址**还需要多少笔交易**才能证明自己」。建议作为榜单一列展示。

## 6. 可跟单性回测 —— 系统最有商业价值的部分

实现：`smrace/backtest/copyable.py`

**不要展示领头者的 PnL。** 展示的应该是：

> 「如果你在他之后 3 个区块以市价跟进、在他卖出后 3 个区块卖出、按 $500 仓位、扣除 BSC gas、0.25% 交易费和代币税，你会赚多少。」

$$
\text{copy factor}=\frac{R_{\text{copier}}}{R_{\text{leader}}}
$$

**参照量级**：已发表研究在 6,000 个 meme 项目上观测到 smart money 平均收益 **14%**，跟单者在考虑现实摩擦后约 **3%**（≈79% 的 alpha 被吃掉）**[有出处]**。该数字是特定平台、特定样本的观测，**不要当常数外推**，但它给出了正确的心理预期。

**四层衰减，按影响从大到小** **[工程判断 + 基于上述实证]**：

$$
R_{\text{copier}}=R_{\text{leader}}-\underbrace{\Delta_{\text{latency}}}_{\text{进场价差}}-\underbrace{\Delta_{\text{exit}}}_{\text{出场滞后}}-\underbrace{\Delta_{\text{impact}}}_{\text{自身冲击}}-\underbrace{(\text{fee}+\text{gas}+\text{tax})}_{\text{显性成本}}
$$

1. **进场延迟（最大项）**：memecoin 早期价格是**超线性**的。领头者在建池后第 2 块进场、你在第 8 块进场，在 bonding curve 上可能已经是 2–5 倍价差。**这不是「滑点」，这是根本不同的成交价。**
2. **出场滞后（第二大，且不对称）**：你只能在看到领头者卖出上链后才卖，此时他的抛压已经打进价格。在低流动性池里，领头者卖出本身就是砸盘 —— 你卖在坑底。**这是结构性的：出场时你永远是领头者的对手方。**
3. **自身冲击**：跟单资金越大滑点越大；BSC 有公开 mempool，跟单流本身构成可被前跑的信号。
4. **选择偏差反噬**：榜单是回看选出的，上榜那一刻往往正是其运气峰值。

**跟单专用过滤**（在闸门之后再叠一层）：

- 排除 `block_delta ≤ 3` 的进场（跟不上）
- 排除中位持仓 < 5 分钟（跟不上）
- 排除进场时池子深度 < $50k（滑点吃光 alpha）
- 用 T+N 区块的**实际价格**重算「可复制 PnL」，而不是领头者的成交价

**判读**：`copy_factor < 0.3` 基本不值得跟。

## 7. 实时层

实现：`smrace/realtime/watcher.py`

**分工**：离线层（天/周级）负责**选人** —— 重、慢、统计严谨；实时层（秒级）负责**跟人** —— 轻、快，只监听选手池里的地址。
**不要让实时层做评分。**

告警分级：

| 级别 | 条件 | 处置 |
|---|---|---|
| **P0** | main 赛道 + `copy_factor > 0.5` + 池子够深 | 可执行 |
| **P1** | main 赛道，可跟单性未验证或偏低 | 观察 |
| **P2** | sniper 赛道建仓 | **只作信号源，不跟单** |

**共识窗口**：多个独立选手在 15 分钟内买入同一代币，是比任何单点信号都强的证据。告警里带 `n_confirm` 字段。

## 8. 常见排名设计错误对照表

| 错误做法 | 后果 | 修正 |
|---|---|---|
| 按累计 USD PnL 排序 | 榜首全是巨鲸和 MEV 机器人 | 收益率 + 风险调整 + 横截面名次 |
| 按胜率排序 | 榜首全是狙击 / 三明治（87%+ 胜率） | 最小样本 + $\mu-3\sigma$ + 净化层 |
| 不做实体聚类 | Sybil 的幸运分身占据榜首 | §2 |
| 不做多重检验校正 | Top 100 绝大多数是噪音 | BHY + 置换基准线 |
| 用外部 K 线给 swap 定价 | 系统性低估滑点 | 用 counterparty execution price |
| 只统计 realized PnL | 忽略套牢仓位，严重高估 | realized + unrealized 双列 |
| 空投 / 转入按零成本 | 无限 ROI 污染 | 按转入时市价 + 单独打标 |
| 相邻间距判并列 | **全场并列第一，名次信息归零** | 与并列组组首比较（§4.2） |
| 无脑上 DSR 硬闸门 | **真高手被全部误杀** | 序数为主闸门，DSR 降级为诊断（§5.4） |
| 固定榜单不滚动 | alpha 衰减后仍在推荐 | 滚动窗口 + Elo-MMR 的时间扩散 $\gamma^2$ |

**结果对 `min_trades` 和 `FDR` 完全不敏感 —— 这本身是最重要的一条发现。**

说明真正起作用的约束是 **§5.2 的置换噪音基准线**（`floor = 3.74`，观测最大 `8.55`），

**工程含义**：调参精力应该花在**噪音基准线的标定**上（置换检验的 B 次数、
是否按参赛场次分层、是否模拟真实的代币相关结构），而不是在 FDR 目标值上纠结。
`min_trades` 同理 —— `min_races ≥ 10` 已经在闸门里做了更强的把关。

### 9.2 真实数据上怎么验证（没有 ground truth 时）

`python -m smrace.cli oos --split 0.67`

用前 67% 的时间选人，看这批人在**没参与选拔的后 33%** 里表现如何，
与「同期落选者」做对照。这直接回答框架最想回答的问题：
**选出来的人，是不是只是过去运气好？**

关键设计：对照组是「同样过了净化层、同样有足够样本、只是没过统计闸门」的那批人。
拿选中组去和全体（含机器人和一次性地址）比，会得到一个虚高到没意义的差距。

合成数据上的结果：

```
[OOS] 训练期 57,797 笔 / 测试期 28,472 笔
[OOS] 选中 5 人，对照 808 人

  选中组   n=   5（测试期仍活跃 5）  中位名次 z=+4.04  中位收益率=+54.0%
  对照组   n= 808（测试期仍活跃 784）  中位名次 z=-0.11  中位收益率=-35.9%
  置换检验 p(名次 z)=0.0002   p(收益率)=0.0002
  选中组在测试期跑赢对照组中位的比例：100%
  选中组测试期失活率：0%
```

判读：
- **两项 p 都 > 0.05** ⇒ 优势没延续到样本外，很可能只是过去运气好，不要上跟单。
- **失活率高** ⇒ 就算统计显著也没用，跟不了一个已经不交易的地址。
- 合成数据上显著是**应该的**（技能是内置的）；真实数据上显著才有信息量，
  且要预期比这弱得多。

统计量用**中位数差的置换检验**而不是 t 检验：样本小、分布厚尾，t 检验不可信。
