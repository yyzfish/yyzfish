# 03 · 接入真实数据源

从合成数据切到链上数据的完整步骤。**按顺序做，每步都有验收标准。**

## TL;DR — 一条命令

```bash
export DUNE_API_KEY=...
export SMRACE_BNB_PRICE_FLAT=600        # 先跑通用固定价，正式请喂 CSV

python -m smrace.cli bootstrap --days 7 --max-tokens 800
```

它会依次：**校验凭证（0 credit）→ 建 Query → 估出这次的账单 → 停下来**。
确认账单可接受后，加 `--yes` 才会真跑：

```bash
python -m smrace.cli bootstrap --days 7 --max-tokens 800 \
    --query-id <id> --estimate-query-id <id> --yes
```

**默认在花钱之前停下来**是刻意的：估算免费，正式查询不免费。

Free 档没有 CRUD API，自动建 Query 会失败——这时它会把 SQL 写到
`out/dune_queries.sql`，你手工贴进 Dune 存成 Query，再把 id 传回来即可。

## 0. 心理准备：接线的失败模式不是「报错」，是「静默算错」

这一层最危险的地方在于，字段名或单位错了，管线照样跑完、照样出榜单，
只是榜单是错的。三个典型：

| 错误 | 现象 | 后果 |
|---|---|---|
| wallet 取了 `Buyer`/`Seller` 而不是 `tx.From` | 榜首是一个交易量惊人的「超级选手」 | V3/Infinity 上那是 **Router**，成千上万个用户被归成一个地址，框架彻底失效 |
| GasPrice 单位当成 wei（实际是 gwei） | gas 成本小 9 个数量级 | 净 PnL 高估，高频地址被系统性抬高 |
| 没接转账流（flows） | `cost_coverage` 恒为 1.0 | 「收币→卖出」的老鼠仓算成**无限 ROI**，直接占据榜首 |

所以第 2 步的探针不是可选项。

## 2. 探针：核对字段映射与单位 ← **最重要的一步**

```bash
python -m smrace.cli probe --source bitquery --minutes 10
```

它会拉 10 分钟真实数据，打印归一化前后的对照，并自动做三项合理性检查：

```
✅ gas 中位数 $0.1080（BSC 典型 $0.05–0.3）
✅ 最活跃地址占比 2.3%
   覆盖 4,182 个地址 · 913 个代币 · venue=['pancake_swapv2', 'pancake_swapv3']
```

> 探针只拉 10 分钟数据，成本可以忽略 —— 但如果走 Dune，它同样要消耗 credit，
> 建议先用 Bitquery 的首月免费额度做探针。

**验收标准**

| 检查 | 通过 | 不通过时改哪里 |
|---|---|---|
| 有成交返回 | > 0 笔 | `bitquery._map_trade()` / `dune._map_row()` 的字段名 |
| gas 中位数 | $0.005–2 | `BitquerySource.gas_price_unit`（wei/gwei/bnb） |
| 最活跃地址占比 | < 30% | **wallet 取错了，多半取成了 Router** |
| venue 列表 | 含 v2 / v3 / infinity | Infinity 没出现 ⇒ 数据源没收录，需自建索引补 |

一笔都拉不到时，按探针提示的三步排查：凭证 → 字段名 → `constants.QUOTE_TOKENS`
是否覆盖了实际的 quote 侧资产。

## 3. Dune：先算账单，再存 Query

### 3.1 免费额度能跑多大

Dune Free 档 **2,500 credits/月**，导出按 **20 credits/MB** 扣，
换算下来大约能导出 **31 万行**。而 BSC 全量 `dex.trades` 一天就远不止这个数 ——
**直接拉全量在免费档上是不可能的**。

好在这个框架只关心 meme / 新币，窄范围 SQL 用三层收敛把量砍下来：

1. 只要**窗口内首次出现**的代币（老币不是标的）
2. 只要**参与地址数 ≥ 5** 的代币 —— 参与者不足连一场比赛都开不起来
3. 按活跃度取 **Top-N** 代币，硬性封顶

第 3 条是**有损**的，被砍掉多少行会在 `estimate` 里明确报出来。

### 3.2 跑前先估

```bash
python -m smrace.cli sql --days 7 --max-tokens 800 > dune_queries.sql
```

输出里有四段：① 成交明细 ② 成本估算 ③ 建池区块 ④ Infinity 收录自检。
**先把第 ② 段存成 Query**，它只返回 6 个聚合数，几乎不耗额度：

```bash
python -m smrace.cli estimate --estimate-query-id <id> --days 7 --max-tokens 800
```

```
窗口 7 天  ·  单笔 ≥ $10
  全量成交                 8,412,330 行
  其中新币且够开比赛          612,004 行（3,180 个代币）
  Top800 截断后实际导出       241,880 行
  ⚠️ 被截断丢弃              370,124 行（2,380 个代币）—— 调大 --max-tokens 可纳入

收敛后（本次实际导出）：241,880 行 ≈ 96.9 MB
  档位             credits        超额成本         占免费额度
  free             1,937      $96.85           77%
  analyst            969      $18.17             —
  plus               194       $3.10             —

✅ 放得进 Free 档 2,500 credits/月（用掉 77%）
```

（以上是**示意数字**，真实值取决于当时的链上活跃度。）

不满意就调这三个旋钮，直到放得进额度：`--days` / `--min-usd` / `--max-tokens`。

### 3.3 一个必须知道的定价陷阱

超额补 credit 的单价：**Free $5.00/100 · Analyst $1.875/100 · Plus $1.596/100**。

也就是说**在 Free 档超额跑，单价比升级还贵 2.7 倍**。
要么严格控制在 2,500 credits 内，要么直接升档 —— 卡在中间是最贵的选择。

### 3.4 存 Query 前先自检 Infinity

```sql
SELECT DISTINCT project, version FROM dex.trades WHERE blockchain='bnb'
```

**Infinity 没被收录就必须自建索引补这一块**，否则新盘/高频那段的聪明钱会整段缺失。

## 5. 补齐两块，否则结果不可信

接线初期最容易「先跑起来再说」，但下面两块缺失会让榜单系统性失真：

### 5.1 转账流（flows）

`fetch_flows()` 目前是 `NotImplementedError`。不补的后果：

- `cost_coverage` 恒为 1.0 → 空投 / 老鼠仓的**无限 ROI 完全不被拦截**
- 空投盈亏无法从「交易能力」里剥离
- 同实体内部转账被当成真实买卖，**同一笔盈利重复计两次**

要查的表：Bitquery 的 `EVM.Transfers`，Dune 的 `bep20_bnb.evt_Transfer`。
映射到 `models.Flow`，用 `constants.BRIDGE_ADDRESSES` / `CEX_HOT_WALLETS` 归类 `FlowKind`。

### 5.2 原生币资金流（funding）

反 Sybil 的规则 A / B / E（共同资金源、gas 加注方、利润归集）全都依赖它。
没有它，只有行为聚类规则生效，**一个操盘手的 20 个分身很可能不会被合并** ——
而这正是榜单最隐蔽的污染源。

管线在缺失时会打印警告，不要忽略它。

### 5.3 真实 launch_block

拿不到建池事件时，loader 会用「首笔成交区块」近似。这会让 bundler 判定偏松 ——
因为你观测到的第一笔本身可能就是 bundler 的那笔。生产环境务必接 `fetch_tokens()`。

**Four.meme 特别注意**：曲线阶段的交易不在 `dex.trades` 里，毕业事件是从
Four.meme 合约（`0x5c95…`）发出的，不是 Pancake Factory。只靠 Factory 事件
会把 launch_block 记成「毕业时刻」，导致所有 `block_delta` 失真。

## 6. 验证：真实数据上没有 ground truth，用时间外样本

```bash
python -m smrace.cli oos --source dune --days 90 --split 0.67
```

用前 67% 的时间选人，看这批人在**没参与选拔的后 33%** 里表现如何，
与「同期落选者」做对照（对照组是同样过了净化层、只是没过统计闸门的那批人 ——
拿选中组和全体比会得到一个虚高到没意义的差距）。

合成数据上的输出长这样：

```
[OOS] 训练期 57,797 笔 / 测试期 28,472 笔
[OOS] 选中 5 人，对照 808 人

  选中组   n=   5（测试期仍活跃 5）  中位名次 z=+4.04  中位收益率=+54.0%
  对照组   n= 808（测试期仍活跃 784）  中位名次 z=-0.11  中位收益率=-35.9%
  置换检验 p(名次 z)=0.0002   p(收益率)=0.0002
  选中组在测试期跑赢对照组中位的比例：100%
  选中组测试期失活率：0%
```

**怎么读**

- **两项 p 值都 > 0.05** → 优势没延续到样本外，很可能只是过去运气好。**不要上跟单。**
- **失活率高** → 就算统计上显著也没用，跟不了一个已经不交易的地址。
- **合成数据上显著是应该的**（技能是内置的）。真实数据上显著才有信息量，
  而且要预期比合成数据弱得多。

## 7. 实时层

`BitquerySource.stream()` 目前是 `NotImplementedError`，接线要点：

- **不要轮询。** BSC 出块 0.45s ≈ 192,000 块/天，轮询间隔必须 < 450ms 才不丢块。
- 自助档最快是 **CoreCast gRPC（~300ms）**，其次 WSS（~1s）；Kafka（~400ms）只有 Enterprise。
- **mempool 流要 Scale 档起。**
- 复用 `_map_trade()` 做归一化 —— 实时和离线共用同一套映射，避免两边口径漂移。

选手池由离线层产出（`realtime.roster_from_leaderboard`），实时层只读。
**不要让实时层做评分。**

## 8. 上线检查清单

- [ ] `probe` 三项合理性检查全绿
- [ ] `SELECT DISTINCT project, version` 确认 Infinity 覆盖情况
- [ ] 用一笔真实交易 receipt 核对 V3 / Infinity 的 topic0（`constants.TOPIC0`）
- [ ] `BRIDGE_ADDRESSES` / `CEX_HOT_WALLETS` 两张白名单已填
- [ ] 管线第 [2] 步的 `cost_coverage` 分布不是恒 100%
- [ ] 管线第 [1] 步能看到「合并出 N 个多地址簇」，N > 0
- [ ] `fetch_tokens()` 已接入，Four.meme 的 launch_block 来自 `TokenCreate` 而非毕业事件
- [ ] BNB 价格喂的是时间序列而不是固定值
- [ ] `oos` 的两项置换检验显著，且选中组失活率可接受
- [ ] Bitquery archive 数据集的计费与历史深度已与销售确认
- [ ] `estimate` 的预估与实际扣费对得上（首跑后校准 `--bytes-per-row`）
- [ ] 如果开了 Top-N 截断，被丢弃的代币数已记录在案
